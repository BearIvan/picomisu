# Changelog

Picomisu Source releases for the PICO 4 Pro (PICOA8110). Newest first.

Release 2.00 and later are built on CodeLinaro LA.UM.8.12.c3-64900-sm8250.0; 1.x on AOSP android-10.0.0_r47.

## 2.21

the factory toybox is carried (PICO applets without source: gtop GPU top over /proc/gpu_procs that SysPerfMonitorService runs every 10 s, top OOM fields, f2fs pin, swap) together with the gtop symlink.

## 2.20

libmediametrics off by default as on the factory (EnabledProperty_default 0; no media.metrics service on PICO OS): media clients no longer block looking it up (seethrough settings hung on exit).

## 2.19

the first-boot logger restarts logcat when logd drops it (2.18 kept only the first 23 s); SELinux rules for the Source-only denials (first-boot logger, nettools on the FT daemon) - every other denial on 2.18 is denied by the factory policy as well.

## 2.18

the first boot after a Source update is logged to the cache partition (source-firstboot.sh, synced every 5 s) to catch the logo/black-screen hang seen after the 2.16 and 2.17 updates; the cache partition is mounted at post-fs.

## 2.17

CFI enabled as on the factory image.

## 2.16

Source Update finds the update server on the local network (no typing); source_updaterd detects the init-mounted cache partition.

## 2.15

first release delivered by the in-headset Source Update (test of the update path: no functional change).

## 2.14

in-headset Source Update (com.picovr.updatesystem replaces the factory SystemUpdate2, embedded in PICO Settings like the original; signed Source OTA packages from a configurable server or /sdcard/dload; source_updaterd stages them and reboots to the updater).

## 2.13

picofacialdatadaemon sends the first MARCO at once (the client was dropped every 30 s); image on the 2.12 block layout.

## 2.12

ActivityDisplay.onDisplayChanged ext hook last (factory order); TEMP display reorder caller logging; image built on the 2.11 block layout (base_fs) with release-independent UUID/salt.

## 2.11

picofacialdatadaemon single socket reader (no spurious client drops while the headset sleeps) and 25 Hz send cap.

## 2.10

business eye tracking mode for pxreyetrackingservice only (libpxreyetracking_tob preloaded through an override of its init service; PXR::EyeUtil::isDebugBusiness), nettools /proc rule for picofacialdatadaemon.

## 2.09

picofacialdatadaemon (fork of thoricelli/PicoFacialDataDaemon, external/picofacialdatadaemon) as an init service with its own SELinux domain instead of the Magisk module.

## 2.08

init logs ctl.* messages like the factory (DEBUG, silent on unknown names) - the per-second 'Could not find uimRemoteClient0' ERROR line went to the ttyMSM0 UART console on CPU7 and stalled the XR compositor ATW pass (TEARSCREEN_COST_ABNORMAL stripe once a second).

## 2.07

Process.setProcessFreezeGroup JNI takes (pid, uid) as on the factory (the swapped arguments froze system_server on the first VRShell keep-alive freeze -> endless loading after setup); trial diagnostics (triallogcat/trialsnap) dropped, only the trial USB/TCP ADB enablement kept.

## 2.06

on-device fixes after 2.05 (PhoneWindowManager.checkAddPermission allows PICO type 2998 floating windows: iFlytek symbols panel; gtop symlink not carried until the factory toybox gtop applet is ported) and the full native comparison fixes (init/fs_mgr stabd notifications, sigchain Unity handler, app_process signal 58, LightsService, libcutils jank tracing, libmeminfo GFX_cached/MemAvailable, tinyalsa/libmtp/OMX logs, VR audio service via factory libvraudio).

## 2.05

device boot fixes (liblog Smartisan buffers sysevent/sysfatal/untrustedapp, libbpf_android loadProgWithUnlink, init panel -> ro.pvr.hmd.type INNOLUX5K) and PICO port pass 6 (ART/libcore Smartisan extensions, bionic GWP-ASan, audio updateSecondaryOutputs + libeffects spatializer, libmmparserextractor, WFD/HDCP + ANetworkSession/ParsedMessage, small PICO/Smartisan residue, framework-res identical to the factory, factory locales), CFI off for test builds as on the factory.

## 2.04

PICO port pass 5 (Java and native PICO residue, libprocessgroup PICO groups, later-AOSP backports, Smartisan residue and CAF drift, installd and init scripts byte-identical to the factory; outputs/audit/rebase-log.md). init.rc is now the factory file: init_rc_edits keep only the trial ADB/diagnostics appends (the others duplicated factory-fs/mmi triggers and cgroup lines in 2.00-2.03), and factory_over_source drops the files Source now builds byte-identical.

## 2.03

PICO port pass 4 (Smartisan layer: the factory sys-services.jar and sysmonitor-services.jar on the system server class path before services.jar as on the factory, with the services.jar Smartisan layer and hook sites they link against and call into; cgroup freezer, QuickBoot, meminfo, sensor freezing) - outputs/audit/rebase-log.md. source-2.02: Source 2.02: PICO port pass 3 (key policy, power, battery, shutdown animation, ApiLayer; WM/activities/IME/displays via IExt*; SurfaceFlinger/libgui; libEGL/libvulkan PICO layers, hwui RenderMonitor; audio Java/JNI, runtime; bootanimation; hidden-API flags) — outputs/audit/rebase-log.md.

## 2.02

PICO port pass 3 (key policy, power, battery, shutdown animation, ApiLayer; WM/activities/IME/displays via IExt*; SurfaceFlinger/libgui; libEGL/libvulkan PICO layers, hwui RenderMonitor; audio Java/JNI, runtime; bootanimation; hidden-API flags) — outputs/audit/rebase-log.md.

## 2.01

PICO port pass 1 on the CAF base (frameworks/base wm/input/IME/power/brightness, native, Wi-Fi, audio; outputs/audit/rebase-log.md), factory CPU variants kryo300/cortex-a75, factory framework-res overlay and PRODUCT_CHARACTERISTICS device,nosdcard, factory PermissionController/SettingsProvider/InProcessNetworkStack (outputs/audit/config.md PKG-01, SET-01..06).

the factory libmmparserextractor.so (does not load on Source, media.extractor aborted in a loop) is no longer carried. source-trial-01c: boot-time USB ADB and /cache diagnostics: on 01b the headset still showed only MTP about 15 s after reboot, i.e. init applied persist.sys.usb.config=mtp at the boot trigger before the 01b property rule ran (AdbService reads persist.sys.usb.config once when system_server starts). 01c sets persist.sys.usb.config=mtp,adb in an init.rc boot action, which is queued before the imported init.usb.rc boot action that copies it to sys.usb.config, sets Settings.Global.adb_enabled=1 after start, and writes logcat (all buffers incl. kernel) and state snapshots to the unencrypted /cache so a black-screen boot can be diagnosed from the offline recovery. source-trial-01b: the factory vendor/build.prop sets persist.vendor.usb.config=mtp and vendor init.qcom.usb.rc copies it to persist.sys.usb.config; after the userdata wipe no stored adb setting exists, so AdbService (reads persist.sys.usb.config at start) disabled ADB and 01a exposed only MTP. An init.rc rule rewrites persist.sys.usb.config=mtp to mtp,adb. source-trial-01a: /adb_keys: on the device the factory vendor/default.prop (ro.adb.secure=1) is loaded after system/etc/prop.default and overrides the trial ro.adb.secure=0, so adbd asked for key authorization after the userdata wipe and the VR shell showed no prompt. Everything else equals source-trial-01. Original decision: First Source trial-boot system image. The Source system image of aosp_pico4pro-userdebug (framework, services, runtime/ART and the other APEXes, SELinux platform policy, vold, native libraries, boot image of 21 JARs) is the base. On top of it the factory 5.13.7 system components that the Source build does not provide are carried over byte-exact (only the certificate of platform-role APKs is replaced), so that PICO VR services, shell, launcher, apps, configs and prebuilts exist. vendor, product, odm, boot/kernel stay unchanged factory/current. Every carried ELF/JAR/APK is checked against the Source libraries/class path (tools/check-source-image.py).
